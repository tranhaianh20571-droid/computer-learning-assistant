# Cover Pipeline Contract

Status: implementation contract for the approved cover pipeline; supplier acceptance remains separate.

- GET `/api/planning/{kind}/{target_id}/cover/preflight` reads owner-validated target/title/title_hash, active image-generation configuration metadata and `course_topics=[{title,title_hash}]`. It creates no task or grant and never probes a supplier.
- POST `/api/planning/{kind}/{target_id}/cover/automatic` accepts explicit `external_authorized`, pinned `config_id`/`config_version`, `title_hash`, optional `idempotency_key`, `authorization_scope` (`exact_target` or `route_and_confirmed_courses`) and the exact `course_topic_hashes` returned by preflight for hierarchy consent. Missing consent or stale title/configuration/course-topic set rejects image generation. No current configuration is silently selected.
- Task, private asset, cover-state pointer and task-bound disclosure grant share one SQLAlchemy transaction. Idempotency includes owner, target kind/id, exact outbound-title hash, requested method, pinned configuration/version, scope and user request key.
- `authorization_scope=exact_target` cannot authorize other resources. A route hierarchy grant may derive only to actual course IDs in that route's current confirmed version; derivation must revalidate the root grant, owner and root configuration. Cover validation pins both the exact persisted `grant_id` and terminal root (`parent_grant_id` for the one-level route-to-course chain, otherwise `grant_id`); a newer direct grant on the same task cannot replace either pin. Root revocation invalidates derived permission. Unconfirmed candidate identities and unrelated course IDs cannot receive derived grants.
- Cover ownership follows the library's actual top-level grouping, including retained historical memberships and detachments. Responses expose `cover_eligible`, `cover_owner_kind`, and `cover_owner_id`. Grouped courses return `status=suppressed` with no image/task/asset; generation, provider dispatch and publication all recheck eligibility. Historical assets and grants are retained.
- One planning result has one top-level cover: a route cover or an independent course cover. New UI requests use `exact_target`; route confirmation does not enqueue covers for member courses or derive new image grants. Existing hierarchy grants remain historical records.
- Pending or valid current output for the same owner, target and topic is reused across repeated user request keys and repeated confirmations. Explicit `regenerate=true` requests may replace it after normal authorization checks. Draft confirmation and planning-scope conversion reuse valid assets through an owner-checked byte copy where target identity changes; they do not make another supplier request.
- The persisted recipe reports `requested_method`, `actual_method`, `fallback_reason` and terminal `error_code`; ordinary asset `method` remains a compatibility representation of the actual published asset. Existing current images remain displayed while a replacement is pending or fails. Normal UI omits method and fallback labels.
- Missing explicit image configuration may use a local procedural request. Provider timeouts, connection failures, rate limiting and server failures are the only automatic image-to-procedural fallback conditions. Missing/revoked/expired disclosure, configuration/version mismatch, cancellation, lease loss and target deletion never become successful fallback output.
- Cover GET is read-only and does not kick, retry or recover tasks. A lifecycle-managed, independent two-worker dispatcher scans persistent queued tasks and abandoned live-deadline leases. Total deadline expiry is terminal and never automatically requeued. Retry/regenerate requires explicit POST; image retries revalidate task-bound authorization.
- Image transport resolves and rejects every non-global destination, then connects to that exact IP with the approved hostname preserved in Host/TLS SNI. It uses no environment proxy, retries or redirects, bounds responses, and rechecks task/grant/configuration immediately after DNS, before sending and at every streamed chunk. Only OpenAI-compatible `/images/generations` with `b64_json` is implemented, not vendor asynchronous jobs or arbitrary returned URL fetching.
- Dispatcher shutdown joins its loop for at most two seconds and does not wait on blocked worker I/O. The stop gate forbids late image sending/publication; restart is refused while old workers remain. Python cannot forcibly terminate an active thread, so a stuck provider call remains subject to its configured HTTP timeout and process-exit cleanup.
- No title, prompt, response/image bytes, credentials, endpoint or supplier exception text enters runtime/task-event/audit telemetry. Preflight title and configuration metadata are private owner-scoped business payloads.

Verification uses synthetic adapters and isolated test schemas only. No live database migration, vendor request or Logfire change is part of this contract.
