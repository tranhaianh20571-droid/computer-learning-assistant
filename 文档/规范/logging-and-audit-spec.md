# 通用日志、任务事件与审计规范

> 版本：v2.0（通用版）｜2026-09-28，自项目版 v1.0 泛化而来，可独立复制到其他项目使用。  
> 适用范围：任何包含 Web 服务端、后台任务进程、本地代理/连接器和外部服务调用的多用户系统。  
> 本文中的"必须"用于落实隐私、诊断、权限、恢复与删除要求；具体保留天数是实施建议，各项目按自身隐私声明与业务承诺另行确认。

## 1. 目标与边界

日志应回答四个问题：**哪个阶段失败、同一任务经历了什么、谁做了敏感操作、系统是否达到已确认的恢复与性能边界**。诊断过程默认不依赖查看用户上传内容、提问、模型提示词、图像或音频正文。日志本身不能充当用户业务记录，也不能决定任务是否已完成。

本规范覆盖浏览器、服务端 API、后台 worker、本地代理/连接器、外部服务适配器以及删除清理流程。外部供应商自己的日志和保留策略不受本系统控制；上线前应核对并向用户说明。


| 数据类型      | 用途                              | 存放与对用户的关系                                     |
| --------- | ------------------------------- | --------------------------------------------- |
| **运行日志**  | 定位错误、超时、重试及跨进程调用                | 结构化 JSON，由服务端收集；不向普通用户开放原始日志。                 |
| **任务事件**  | 呈现上传、解析、外部调用、生成、保存等长任务的进度及结果    | 持久写入业务数据库；按资源所有权查询，供页面断线恢复。它是用户可见任务状态的依据。     |
| **安全审计**  | 追踪账户生命周期、授权变更、凭据配置、数据出口、删除和拒绝访问 | 独立的追加式审计表/流，限制写入与读取角色；不包含操作对象的正文。             |
| **指标与追踪** | 统计耗时、错误率、队列积压、恢复质量              | 使用聚合指标和 trace/span；指标标签不得使用用户 ID、资源 ID 或问题内容。 |


四类数据分开设计、存储和授权，不能用其中一类充当另一类：运行日志不是用户状态，任务事件不是诊断日志，审计不可被应用逻辑改写，指标不承载明细。

## 2. 通用字段与关联规则

所有服务端日志采用一行一个 UTF-8 JSON 对象，不通过拼接自由文本承载结构化字段。时间统一记录 UTC ISO 8601，同时保留单调计时得到的 `duration_ms`；前端展示时转换为用户时区。字段名、事件名和错误码由项目的**统一注册表**管理，不允许各模块随意造同义字段；注册表是本规范在各项目落地时的唯一扩展点。


| 字段                                           | 要求      | 说明                                                        |
| -------------------------------------------- | ------- | --------------------------------------------------------- |
| `schema_version`、`timestamp`、`level`、`event` | 必填      | 例如 `1`、UTC 时间、`INFO/WARN/ERROR`、`job.stage.failed`。       |
| `service`、`environment`                      | 必填      | `api/worker/connector` 等；部署环境，不含主机上的个人路径。                 |
| `trace_id`、`span_id`                         | 有处理链时必填 | 随机生成；API → 任务 → worker → 连接器保持关联，不嵌入账号或文件信息。              |
| `request_id`、`task_id`、`attempt`             | 适用时填写   | HTTP 请求、持久任务和本次尝试的内部标识。相同任务重试保留同一 `task_id`，`attempt` 递增。 |
| `actor_id`、`resource_type`、`resource_id`     | 适用时填写   | 内部不透明 ID；不记录邮箱、业务标题、文件原名。拒绝访问时记录请求者和被请求的资源类型/不透明 ID。      |
| `stage`、`status`、`error_code`、`duration_ms`  | 阶段结束时填写 | 阶段和错误码为受控枚举，耗时为非负整数。                                      |
| `config_id`、`config_version`、`capability`    | 外部调用时填写 | 关联个人或管理员的外部服务配置；不记录密钥、服务地址、完整请求或响应。                       |
| `unit_no`、`part_id`、`generation`             | 适用时填写   | 定位分片处理（页/区域/分块）的失败单元及过期生成结果；不放坐标截图或处理正文。                  |


HTTP 入口接受并验证 W3C `traceparent`，无有效值时生成新的随机 trace ID；内部异步任务保存其上游 trace ID，并建立新的 span。对外部供应商只发送业务所需的头和数据，**不把用户身份、资源标题或私密字段写进 trace 上下文**。供应商返回的 request ID 经长度和字符校验后可保存为 `external_request_id`，只供排障。

示例（ID 均为不透明占位值；生产环境应使用随机、不含语义的标识）：

```json
{"schema_version":1,"timestamp":"2026-09-28T08:12:30.000Z","level":"ERROR","event":"job.stage.failed","service":"worker","environment":"production","trace_id":"4bf92f3577b34da6a3ce929d0e0e4736","span_id":"00f067aa0ba902b7","task_id":"task_7f3a","attempt":2,"actor_id":"user_4c21","resource_type":"file","resource_id":"file_81b0","stage":"external_call","status":"failed","error_code":"EXTERNAL_CALL_TIMEOUT","duration_ms":180003,"unit_no":37,"capability":"admin_ocr","config_id":"config_7e52"}
```

不得在 `message`、异常堆栈或自定义字段里绕过第 6 节的禁止记录规则。

## 3. 阶段、事件与错误码

### 3.1 任务阶段与场景

任务阶段由项目注册表定义固定枚举，命名使用小写领域词，必须覆盖五类：**接收与校验、解析与转换、外部调用、持久化、清理**。阶段事件采用固定状态：`started/succeeded/partial/failed/retry_scheduled/cancelled/stale_discarded`。分片处理（页、区域、分块）需要在任务事件中保留单元序号与失败范围，使用户能重试失败部分而不重复纳入成功部分。

各场景下运行日志/任务事件应能定位与禁止记录的内容：


| 场景                    | 应能定位到                                            | 不记录的内容                  |
| --------------------- | ------------------------------------------------ | ----------------------- |
| 上传与文件解析               | 类型校验结果、大小区间、单元总数与逐单元状态、失败码、超限类型                  | 原文件名、原文件路径、文本正文、页面图像    |
| 外部服务调用（OCR/搜索/模型/语音等） | 配置与版本的内部引用、单元序号、是否获外发确认、超时/输出缺失/格式错误、是否已保留原件     | 上传内容、外部返回正文、中间截图、密钥     |
| 检索与联网搜索               | 选定资料数量、可用片段数量、成功状态、结果数量、获取时间、离线继续决定              | 提问、搜索词、检索片段、网页正文、完整 URL |
| 内容生成（结构化输出/对话）        | 路径/模式类型、会话代（generation）、输出校验通过/失败、首段等待耗时、旧结果是否丢弃 | prompt、模型回答全文、用户问题、业务标题 |
| 媒体与长任务（语音/渲染/转码等）     | 步骤与内容版本、schema 校验结果、是否含用户原图、生成/缓冲状态和耗时           | 输入文本、音频/图像字节            |
| 状态保存与恢复               | 保存序号、成功与否、恢复点年龄/回退幅度、冲突/过期写入                     | 业务正文、完整操作历史             |
| 删除与备份恢复               | 墓碑 ID、清理阶段、待清理/已清理对象数、超期状态、恢复后墓碑重放结果             | 被删除内容、原文件名、用户凭据         |


### 3.2 错误码

错误码由系统定义，和展示给用户的提示一一映射；供应商异常不得直接显示或写入日志。项目注册表初始可包含 `UPLOAD_TYPE_REJECTED`、`UPLOAD_QUOTA_EXCEEDED`、`INPUT_ENCRYPTED`、`UNIT_RENDER_FAILED`、`EXTERNAL_CALL_TIMEOUT`、`OUTPUT_INVALID`、`QUOTA_EXCEEDED`、`SAVE_FAILED`、`STALE_RESULT_DISCARDED`、`CLEANUP_OVERDUE` 等。新增错误码时必须说明：责任阶段、是否可重试、是否对用户可见，以及对应的告警级别。

### 3.3 级别与频率


| 级别      | 使用条件                        | 例子                                   |
| ------- | --------------------------- | ------------------------------------ |
| `ERROR` | 阶段失败且需要用户处理、自动重试耗尽，或数据一致性受损 | 外部调用超时、状态保存失败、清理逾期。                  |
| `WARN`  | 已降级、异常但可恢复、过期结果被拒绝，或授权访问被拒绝 | 搜索失败后明确离线继续、连接器离线、旧 generation 结果丢弃。 |
| `INFO`  | 重要状态变更和阶段汇总                 | 任务受理、逐单元处理汇总、版本应用、任务完成。              |
| `DEBUG` | 开发环境短期开启的实现细节               | 内部重试调度、校验分支；仍遵守所有脱敏规则。生产默认关闭。        |


任务阶段开始/结束/失败及所有安全审计不采样。周期性自动保存（如播放 checkpoint、编辑草稿）**成功不逐条写 INFO**，用计数和延迟分布聚合；失败、连续落后和恢复回退超界则逐条记录。大批量分片处理的单单元明细以数据库任务事件为准，运行日志可汇总成功数与失败单元号，避免海量正常日志淹没异常。

## 4. 用户可见任务事件

任务事件与运行日志分开设计。`task_events` 至少有 `event_id`、`owner_user_id`、`task_id`、`subject_id`、`sequence`、`stage`、`status`、`error_code`、`progress_current`、`progress_total`、`created_at` 和可展示的**预先定义**提示模板参数。`sequence` 在同一任务内单调递增；事件写入与任务状态更新同一事务，重复提交靠幂等键/唯一约束去重。事件流断线后按序号或 `Last-Event-ID` 补取，事件过期或序号不连续时返回明确错误（如 `410 events_expired`），客户端改用 REST 全量查询并以当前版本重建界面；补取不得绕过所有权校验，事件流不跨用户。

浏览器可以先显示本地"已提交/处理中"，随后以服务器事件确认。用户看到的"已保存"只来自服务器确认的写入，不来自浏览器定时器或运行日志。失败事件明确告诉用户可重试的单元或阶段；外部服务失败需提供"重试/明确离线继续"选择；过期生成结果只留诊断事件，不覆盖当前会话。普通用户只能读取本人任务事件，管理员不能借诊断入口默认查看用户私密正文。

## 5. 安全审计事件

以下类别的敏感操作写入追加式审计记录，失败尝试也记录结果：账户注册/验证/审批/停用、登录失败计数和锁定、密码重置与会话撤销、凭据与外部服务配置的创建/更新/删除及连接测试、数据出口（外发）确认与撤销、本地代理/连接器配对与撤销、跨用户资源访问拒绝、资源删除与清理、备份恢复。每条至少包含事件名、时间、操作者内部 ID、对象类型及内部 ID、动作结果、`trace_id`；管理员操作还需记录管理员内部 ID。

审计记录不能保存密码、验证/重置令牌、会话 cookie、API Key、个人服务地址、完整文件名或外发内容。审计表使用独立写入接口与权限，应用普通读账号不能修改既有审计行；管理员查询本身也要留下审计记录。安全审计对普通用户界面只暴露必要的个人操作历史，不能作为原始日志下载接口。

## 6. 隐私、脱敏与日志注入防护

采用**字段允许名单优先**：只有项目注册表登记的字段可进入生产日志。项目可通过显式的**内容 trace 通道**（独立事件类型、独立输出口、独立留存策略）记录模型提示词、模型回答与用户问题三项内容；是否开启由配置开关控制，关闭时该通道不得产生任何内容记录。内容通道之外的一切通道（运行日志、任务事件、审计、聚合指标）仍禁止正文类内容。

**任何通道（含内容通道）都禁止记录或透传**：

- 密码、API Key、OAuth/连接器令牌、Cookie、Authorization 头、会话 ID、数据库连接串、加密主密钥；
- 电子邮箱、文件原名、完整本地路径、带查询参数的 URL、用户自填服务地址、原始供应商错误或堆栈中包含的上述值。

内容通道的三项内容字段只做控制字符清理与超长截断，不做值级模式遮蔽；凭据类防护由字段名级禁止名单与凭据掩码机制继续承担。诊断需要供应商信息时记录 `config_id`、协议类别、能力类型和错误码；需要文件信息时记录不透明 `resource_id`、单元序号和大小区间。若安全排障确需 IP，放在受更严权限控制的安全事件中，并确定脱敏及留存规则，运行日志默认不写。浏览器生产版不在控制台打印请求体、私密状态或配置对象。

所有不可信字符串先限制长度、移除控制字符并由 JSON 编码器输出，防止用户文件名、网页内容或供应商错误伪造新日志行。HTTP 框架、反向代理、外部 SDK、异常上报器和连接器都要配置相同的敏感字段过滤；不能只在业务 `logger` 里遮蔽。生产环境对密钥、邮箱、假文件名、含凭据的模型错误做自动化泄漏检查；内容通道需专项断言"内容只出现在内容通道"。

## 7. 指标、告警和留存

指标以阶段与错误类型为低基数标签，例如 `task_stage_duration_ms{stage,status}`、`task_failures_total{stage,error_code}`、`task_queue_depth{stage}`、`save_failures_total`、`save_age_seconds`、`cleanup_overdue_total`、`agent_online_count`。不得把 `user_id`、`task_id`、单元序号、模型名或 URL 放进指标标签。首响等待、暂停响应和恢复回退可用聚合指标观察；性能验收所需的原始耗时按项目验收方案独立留存，生产观察指标不替代验收数据。

至少对以下情况告警：任务队列持续积压、外部调用阶段错误率异常、状态保存持续失败或恢复点年龄超界、清理任务超期、备份轮换超期、审计写入失败、跨用户访问拒绝激增。告警消息只包含环境、阶段、错误码、内部 ID 和仪表盘链接，不附私密内容。

首版留存策略：**运行日志 14 天、安全审计 90 天、聚合指标 90 天、内容 trace 通道按平台容量与隐私声明单独确定**（自建或外置 trace 平台的留存与删除均须纳入下面的删除联动）；具体天数由各项目结合隐私声明、容量和运维责任确认。任务事件按关联资源的生命周期管理；资源删除后立即撤销访问，并在清理过程中删除或去关联其可识别事件及诊断数据，**同时触发外部观测平台中该资源关联内容（trace/提示词版本）的删除任务并核销**。在线数据与备份的保留期限按业务承诺另行确定；备份恢复必须先重放删除墓碑。日志备份和导出副本也必须纳入留存与访问控制，不能成为删除后的隐性副本。

## 8. 实施检查清单

1. 用一个从输入到最终输出的端到端样例，凭 `trace_id + task_id` 串起 API、worker、外部调用与连接器；每一步有阶段和耗时，失败单元可定位。
2. 故意注入故障：外部调用超时、搜索失败、媒体任务失败、状态保存失败、连接器掉线、旧任务迟到，检查任务事件、用户提示、运行日志与审计是否各司其职。
3. 用含测试 API Key、邮箱、敏感正文、查询词及私密 URL 的假数据走上传、连接测试、外部错误和异常堆栈；所有生产日志与告警均不得出现这些值。
4. 验证跨账户资源 ID、文件地址、任务事件和审计查询无法读取他人内容；管理员只能通过受权入口读取审计，原始运行日志有独立访问权限。
5. 删除资源后检查访问立即拒绝、任务结果不复活、在线/备份清理按业务承诺完成，并检查日志和导出副本的留存规则。

## 9. 原生 PydanticAI 迁移实施约定

本项目运行监控选定 `PydanticAI Instrumentation → OpenTelemetry → Logfire`。原生 Instrumentation 的 `include_content`、`include_binary_content`、`include_model_request_parameters` 均关闭；受控运行 trace 和 metrics 不合并原有可选内容通道。使用单一 TracerProvider / MeterProvider；导出过滤字段、异常、事件、资源与指标标签，不将任意模型名、URL、用户 ID 作为指标维度。HTTP 入口仅接受有效 traceparent，不接受 baggage / tracestate；任务持久化必要关联，排队、授权、生成、围栏、事务和发布分开埋点。导出失败不得修改任务事务结果。

错误注册表新增 `OUTPUT_INVALID`（生成阶段、可重试、用户可见、WARN）和 `TASK_CANCELLED`（保存阶段、不自动重试、无告警）；取消及旧围栏失败不允许转换为内容修复或成功结果。外发核验必须有真实任务所有权、当前配置版本和实际范围快照；缺失授权拒绝发送，不为兼容旧夹具放宽生产边界。

后台 `lesson_plan_refine` 是独立持久任务：首段发布后排队，单任务最多三次模型请求，保留租约、期限、版本、材料和外发授权核验。只提交未来会话使用的 `PreparedLessonPlanRow` 缓存，禁止覆盖当前冻结蓝图、教学步骤和首段内容；细化失败不撤销已发布讲解。新任务不自动铸造或扩大用户外发授权。

## ADR-030 逐次模型请求与私有教学内容

`model.request.completed/failed` 独立于 Agent 轮次，记录非负 `duration_ms`、可选 `first_chunk_ms`、任务/配置 ID 与配置版本。失败分类使用 `MODEL_TIMEOUT`、`MODEL_CONNECTION_ERROR`、`MODEL_RATE_LIMITED`、`MODEL_CREDENTIAL_INVALID`、`MODEL_PROVIDER_ERROR`、`MODEL_RESPONSE_TOO_LARGE` 或已有能力错误码，禁止原始错误正文。流式教学快照属于经授权业务内容读取，不属于运行日志、审计、聚合指标、task_events 或内容 trace。选定资料的检索正文不得随提示词进入内容 trace。能力探测的时间、有效期和版本存在能力配置元数据中，不包含模型回答。


## 11. 任务收敛与 worker 恢复补充（ADR-033）

任务截止扫描必须在同一数据库事务内完成任务行、当前尝试和任务事件的收敛：`queued`、`leased`、`running` 到达 `deadline_at` 后进入 `expired`，清除活动租约并使迟到结果只能写 `stale_discarded` 诊断事件。租约失效、取消和截止优先于内容修复或本地 fallback。

错误归一化只允许错误注册表中的代码。异常携带未知或供应商代码时必须映射为 `INTERNAL_ERROR`，仅在受控诊断字段保留短的分类标识，不保留原始消息、堆栈、正文、凭据或 URL。`TASK_DEADLINE_EXCEEDED`、`WORKER_RECOVERY_EXHAUSTED` 和 `WORKER_RECOVERY_FAILED` 分别表示期限围栏、有限恢复耗尽和恢复本身失败；它们均不可被内容 fallback 隐藏。

worker 第二次失败必须调用有界恢复接口；恢复只进行最多两次新事务的终态写入，不重跑模型、不发布内容、不自动创建新任务或新代次，持久模型预算累计值不得清零。任务执行 `generation` 与业务内容 subject 中的代次分离：显式重试只递增执行代次并为后续领取创建新的租约/attempt 行，subject 与业务内容代次保持不变。恢复持久化仍失败时向宿主暴露受控 `WORKER_RECOVERY_FAILED`；任务截止扫描作为后续终态收敛路径。用户查询任务状态时可获得受控 `error_code` 与是否可重试信息。

## 12. 教学配置使用与封面外发授权（ADR-034）

教学生产流程使用当前已启用的能力配置直接开始、恢复和预热，不弹逐讲外发确认。启用内容配置表示用于本用户的课程讲解；启用 TTS 配置表示同时生成讲解语音；`FIRST_PREWARM_ENABLED` 控制有限首段预加载。服务端固定课程、讲次、大纲版本、资料范围、模板和配置版本，任务、短期根授权、授权快照与安全审计仍在同一事务提交。停用配置停止后续外发；自动路径不得替换同配置版本已明确撤销的根或子授权。配置更新、明确恢复和下一讲可取得新的精确快照，worker 自身不得补授权。保留显式预检/确认接口用于兼容和受控调用；封面仍按下述显式授权规则执行。

子任务仅可通过 `derive` 继承根授权的内容类别和范围子集，有效期不超过父授权。每次外发校验整个 `parent_grant_id` 链的所有权、配置版本、地址、撤销状态、有效期与范围；根撤销即时阻止后续外发。外部事务会话的审计写入仅 flush，不单独 commit。旧授权行新增空父指针，不自动补授权。

生图预检固定唯一顶层目标主题摘要及图片配置版本。一次规划只有顶层封面：课程集仅 route 持有封面，仍归属于课程库合集分组的成员 course 不生成、不展示封面，独立 course 持有封面；多合集、历史版本、脱离和删除按课程库实际顶层分组口径判断。新图片请求只授权 exact_target，旧授权、图片资产与任务历史保留；禁止通过继承授权为子课程重绘。草稿到确认、重复确认及同主题重复请求复用已有有效资产或在途任务，显式替换仍校验主题、配置与授权。封面服务入口、worker 外发及发布均复核归属；封面 GET 只读。生成方式、受控失败和本地降级原因保留在后台元数据，正常页面不展示方式标签。封面缺失可显示本地中性占位，已有合法封面在替换失败时继续展示；授权、配置版本、租约、取消与目标失效不得被程序画图 fallback 掩盖。

幂等音频任务只在首次创建时派生授权，重复请求核验既有子授权及其固定根链；子授权撤销不得通过再次派生绕过。自动教学恢复可在当前启用配置下更新过期快照，但已明确撤销的同版本授权阻止自动重绑。工作区分别返回内容与 TTS 可用许可、受控错误、截止与租约时间和可恢复动作，未启用语音时直接展示文字。

教学任务成功必须存在对应内容代次的讲解步骤与有效板书。工作区只读检测成功无产物，不以空列表表示仍在生成；开始/显式恢复和下一段调度可创建每段最多两个独立补生成任务，保留原成功任务、已有产物、执行代次及预算。补生成保持业务内容代次，仍受所有权、配置、撤销、租约、期限及发布事务约束；失败任务仅按既有有界重试契约恢复。后台自动首段预加载在有效缓存期内同一缓存键最多尝试两次，失败自动重试保留 60 秒冷却、每日和队列上限；兼容的主动预生成接口仍受每日和队列上限约束，正常页面不展示预生成入口、缓存状态或命中提示。

## 13. 顶层封面与跨讲预加载（ADR-035）

课程库、总览、封面读取与预检统一返回 `cover_eligible`、`cover_owner_kind` 和 `cover_owner_id`。被合集抑制的课程返回 `status=suppressed`，不返回图片地址、资产或生成任务；生成入口不新增任务或授权，既有子课程任务在供应商调用前收敛为取消。任何历史资产均不得因隐藏而删除。

启用默认预加载时，已确认而未学习的课程后台预取第一讲的首段；正在学习第 N 讲且当前首段有效落盘后预取后继讲次的首段，跨单元按当前大纲顺序选择，末讲不再创建下一讲任务。只预取首段，不创建下一讲活跃会话、不改学习进度；当前讲内部下一段缓存仍保持窗口一。后台补齐与重复进入必须幂等、有每日/库存/队列上限，并优先服务当前课堂。缓存以用户、课程、讲次和内容版本键隔离，旧缓存迁移保留行与当前会话引用，不允许后继缓存覆盖正在消费的首段。

文字与板书合法完成即可消费，语音准备不阻挡首段可用；课堂单段等待语音最多 12 秒，语音失败时直接转文字。转入文字后本段迟到语音不自动插播，后续段可重新使用语音。首段预载失败或过期时按正常按需生成进入课堂，受控错误保留，不以占位正文或授权失败假成功替代。
